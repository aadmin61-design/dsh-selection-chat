# DSH Selection Chat 1.1.1

独立的 DSH 划词引用与侧边聊天插件。只需要本机已有的 DSH **0.2.1-rc.2**，不依赖 Codex、不依赖 codex-dots，也不需要安装 Node/Python/前端环境。无需构建。

[下载安装包](https://github.com/aadmin61-design/dsh-selection-chat/releases/download/v1.1.1/dsh-selection-chat-1.1.1.zip) · [版本发布与校验文件](https://github.com/aadmin61-design/dsh-selection-chat/releases) · [更新记录](CHANGELOG.md)

## 功能

在 DSH 的对话正文中拖动选择文字，松开后出现两个按钮：

- **添加到对话**：在输入框上方显示独立引用卡片，输入框只保留你写的问题。卡片支持多条、展开完整原文和单独移除，不修改已有草稿、附件或引用芯片，也不自动发送。
- **在侧边聊天中提问**：使用 DSH 原生 fork 创建独立分支，在右侧栏显示原生聊天界面；选中文字显示在该分支输入框上方。补充问题、确认模型和权限后点击原生发送按钮。

点击原生发送时，卡片内容才作为引用文字附加到本次消息，发送后的聊天历史包含问题及引用。输入框中不会提前出现长引文。发送成功清除本次卡片，失败则恢复卡片，问题和附件仍由 DSH 自身处理恢复。异步发送期间新增的引用留给下一条消息。只添加引用而没有问题或附件时，原生发送按钮仍为空草稿状态；请补充问题再发送。斜杠命令不消费卡片。

侧边聊天继承原对话**最近已完成轮次**的上下文，并额外带上选中的内容。正在生成中的未完成轮次不会被当作完整历史复制；如果还没有任何已完成轮次，DSH 会拒绝分支，请等首轮结束。模型选择、权限、会话存储和计费采用 DSH 原生规则；不要假设分支模型与原会话一致，请发送前检查。

侧边聊天是普通分支会话，不是自动执行的子智能体任务。主对话不会收到侧边聊天的新消息。多个分支有独立会话 ID，标签尾部的短 ID 用于区分。关闭标签页只关闭视图，不等于停止正在生成的回答；需要停止时点击该聊天的原生停止按钮。会话也可在 DSH 自己的列表中继续。

只在对话正文中显示划词菜单；输入框、设置、其他面板和跨两个会话的选区不触发。支持中文、多行和代码选段。超过 100000 字符会明确提示缩小范围，不静默截断。按 Escape 关闭浮层；键盘选中后可按 Alt+Shift+Q 将焦点移到操作按钮。

## 安装与卸载

1. 在 [Releases](https://github.com/aadmin61-design/dsh-selection-chat/releases/latest) 下载附件 `dsh-selection-chat-1.1.1.zip`，将其中的 `dsh-selection-chat` 文件夹解压到固定位置，例如 `C:\dsh-plugins\dsh-selection-chat`。请选择发行附件，安装更直接。
2. 打开 DSH → 插件 → 添加插件，填写该文件夹的**绝对路径**，安装并启用。
3. 若提示重启，先结束正在运行的任务，再手动重启 DSH。
4. 详情应显示 `@local/dsh-selection-chat`、`v1.1.1` 和组件运行中。

源码安装可直接使用当前包含 `package.json`、`index.mjs`、`client.js` 和 `cordis.patch.yml` 的目录。不需要 `npm install`；本地链接安装后请保留目录。

如果通过 GitHub 的 **Code → Download ZIP** 下载源码，也可以解压后安装：填写实际包含 `package.json` 的文件夹路径，不要填写 ZIP 路径或它的上级目录。安装成功后，打开一个至少完成一轮的 DSH 对话，划选回答正文即可看到操作按钮。

**升级到新版本**：先结束当前发送，解压新包覆盖原插件目录，然后重启 DSH。链接安装会继续使用原路径，请勿在升级后移动或删除该目录。

**从 1.0.0 升级**：先结束当前发送，解压新包覆盖原安装目录中的插件文件，然后手动重启 DSH。若使用源码目录链接安装，本目录已更新，重启加载即可。旧版已经写进输入框的引用属于普通草稿，请手动删掉这部分再重新划词；插件不会擅自识别或删除你的草稿。

卸载请使用 DSH 插件管理器。卸载只移除菜单、样式和侧栏注册，不删除已有聊天，不修改 codex-dots 的设置。主动添加的引用卡片暂存在当前窗口的 sessionStorage 中，切换会话和页面刷新可恢复，窗口关闭后不保证保留；发送成功或移除卡片后清除相应缓存。正常草稿和分支历史由 DSH 保存。若在发送途中刷新，卡片标记为结果未确认，需检查历史后点击“确认重新使用”才会再次附加。单纯选中文字不会保存或发送其内容。

## 手动验收步骤

开发期间不使用 Computer Use，也不自动操作 DSH。以下步骤由用户完成：

| 操作 | 预期结果 |
| --- | --- |
| 打开一个至少完成一轮的普通 DSH 对话，选择回答中的一段文字 | 选区上方或下方出现两个按钮，样式跟随明暗主题 |
| 先在输入框写“我的问题”，再划选正文并点击“添加到对话” | 输入框仍只有“我的问题”，上方出现引用卡片；没有发送消息，没有模型开始运行 |
| 点击引用卡片的 ×，再重新添加两段引用 | 只移除相应卡片，问题不变；两条引用分别显示 |
| 点击“展开”，切换会话再返回，或刷新页面 | 可查看完整原文；引用保留在原会话，不串到其他会话 |
| 划选多行、代码块中的文字 | 引用保留换行和文字；不把选中代码当作命令运行 |
| 划选正文，点击“在侧边聊天中提问” | 右侧打开独立分支，出现原生历史、草稿和发送按钮；引用显示在输入框上方，尚未调用模型 |
| 输入“请解释这段引用”，检查模型/权限，再手动发送 | 本步骤消耗所选模型额度；发出的消息包含问题和引用各一次，卡片清除；回答在相应会话，支持原生 Markdown 和代码高亮 |
| 发送后继续添加新的引用，再发下一条问题 | 新引用只随下一条问题提交 |
| 若遇到发送错误，检查卡片与草稿 | 引用恢复在上方；检查问题内容后手动重试，插件不会自动重发 |
| 点击侧栏原生停止，再继续输入新问题 | 停止/继续遵循 DSH 原生规则，两个聊天互不串台 |
| 切换主对话、返回原对话，再打开已有侧栏标签 | 不重复创建分支或插入已接受的引用，已有历史保留 |
| 在输入框选字，或选区跨过两个聊天面板 | 不出现划词菜单 |
| 快速双击侧边提问按钮 | 同一操作只创建一个分支；界面提示失败时使用“重试打开”复用已知分支 |

如果没有出现菜单或点击无效果，请提供：DSH 精确版本、插件详情状态、是主对话还是侧栏、选中文字的位置，以及出现的错误原文/截图。不要发送登录令牌或完整私密聊天日志。

## 非界面验证

在源码目录使用已有 Node：

```powershell
node --test tests/*.test.mjs
node --check client.js
```

使用本机 DSH 自带 Electron 检查宿主接口（路径按实际安装位置修改）：

```powershell
$env:ELECTRON_RUN_AS_NODE = '1'
& 'C:\Program Files\DSH\DeepSeek Harness.exe' --expose-internals scripts/host-check.cjs 'C:/Program Files/DSH/resources/app.asar/dsh' 2>&1 | Out-String
Remove-Item Env:ELECTRON_RUN_AS_NODE
```

离线测试覆盖引用完整性、卡片增删和存储、会话隔离、发送快照、附件与 queue/steer 透传、失败恢复、资源释放、分支去重和卸载恢复。宿主检查执行安装包中的真实序列化方法，并验证 Cordis 加载和接口契约，**不等同于界面已验收**；实际卡片位置、原生发送和侧边聊天渲染仍需上述手动测试。

兼容范围锁定 DSH 0.2.1-rc.2。该版本没有独立引用卡片的提交扩展接口，因此插件对当前会话的原生序列化入口和默认发送入口做可卸载适配；不修改 DSH 安装文件或拦截按键。DSH 更新后需重新运行宿主检查，不能仅凭版本号假定兼容。

发行包不包含 DSH 的代码、账号、历史或私密日志。这是独立插件，可以单独安装、升级和卸载。
